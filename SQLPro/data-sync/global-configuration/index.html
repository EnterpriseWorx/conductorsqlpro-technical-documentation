Global Configuration

Global Configuration holds Data Sync settings that apply to every sync job: processor threads, staging, max retries, the issue email schedule, and timeouts. The minutes-behind threshold is set on each schedule.

To open the page, select the SQLSync icon on the landing page, then choose Data Sync >> Global Configuration:

Note

You need the SyncUpdate permission to open this page. Data Sync must also be licensed and Sync Feature Enabled must be on under SQLPro >> Administration >> Advanced Settings.

The form is organised into Processing, Issue email, and Timeouts groups:

Select Save Settings to store the values. Thread count changes are picked up when the ConductorSQLPro service restarts. Issue email schedule and timeout changes apply as soon as you save.

Warning

After changing Sync Source Thread Count or Sync Target Thread Count, restart the ConductorSQLPro service.

Processing

Setting Description Default
Sync Source Thread Count Number of worker threads that process source-side sync queue work 1
Sync Target Thread Count Number of worker threads that process target-side sync queue work 1
Use global temp tables for sync staging When on, initial and delta source copies use SQL Server ## global temp tables instead of physical tables in tempdb Off
Max delta/checksum retries Consecutive thrown failures of a delta sync message, or a checksum message on a delta queue, before the table is skipped. Status is left unchanged so the next schedule can retry 99999

Tip

Leave thread counts at 1 unless you have measured that source or target queues are backlog-bound and the SQLPro host can support more parallelism. Raise source and target counts independently based on which side is the bottleneck.

Note

The default Max delta/checksum retries value (99999) effectively disables skipping. When a table is skipped, its sync status does not change. Error Message on Sync Monitoring explains the skip (for example that delta or checksum was skipped after N retries). The table is tried again on the next matching schedule run.

Issue email

SQLPro can email a SQLPro - Data Sync Issues Report when sync configurations have table errors, checksum errors, or tables that have fallen behind. The job uses the mail list configured under SQLPro >> Administration >> Mail.

Setting Description Default
Issue email schedule Hangfire cron for the Data Sync Issue Email Alerts job, in the SQLPro host's local time. Default is 08:00 daily (0 8 * * *) 0 8 * * *

Minutes behind threshold is configured on each schedule as different schedules may need to have different thresholds.

Note

A Change Tracking table counts as behind when its status is syncing (S), it has no error message, and Last Sync Check is older than that schedule's threshold. Destructive Load tables are excluded. A threshold of 0 turns lag alerts off for that schedule. The email is skipped when no configurations currently have issues. Checksum errors in the report do not include tables with checksum status Ignored (see Ignore Checksum Issue). The same rules drive the Issues only toggle and the Behind column on Sync Monitoring.

Timeouts

Setting Description Default
Live-read lock timeout (seconds) Seconds to wait for a lock on live source reads (CHANGETABLE probes, initial SELECT INTO, delta copy, source checksum SELECT) 15
Change tracking command timeout (seconds) ADO.NET command timeout for Change Tracking enable/disable 5
Long SQL command timeout (seconds) ADO.NET command timeout for long SQL (checksums, data-movement probes, temp-table copy/index/count, MERGE, clustered index) 6000
Delta batch read timeout (seconds) ADO.NET command timeout when reading a batch from the delta staging table 300
Fabric COPY INTO timeout (seconds) ADO.NET command timeout for Fabric COPY INTO 1800
