Introduction

Source hosts identify the instances that Data Sync reads from. Sources can be Microsoft SQL Server (Azure SQL, Azure SQL Managed Instance, or on-premises) or MySQL 8+.

To get started, open SQLSync from the landing page, then select Data Sync Source Host Configuration:

Source Host list

The list shows registered source hosts, including the instance name and whether the host is active.

Use Refresh to reload the list. Use the row Edit action to change an existing source host.

Add a source host

Select Add Source Host to open the edit dialog.

Fields:

  • Instance Name - the SQLPro instance (client) to use as the source. Required. Locked after the host is created.
  • Is Active - when off, the host is unavailable for new sync configurations and in all the monitoring screens.

Select Save to create or update the host, or Cancel to discard changes.

Note

Fabric instances cannot be used as sources. PostgreSQL instances cannot be used as sources. MySQL source hosts sync with Destructive Load only. MySQL tables are stored with schema name dbo. The MySQL database name is the source database.

Tip

Register the instance under Administration > Instances before adding it as a source host. Microsoft SQL Server instances can use Windows Authentication, SQL Server Authentication, Microsoft Entra Password, or Microsoft Entra Service Principal. MySQL instances use a username and password.

MySQL type mapping

MySQL column types are converted to SQL Server types on the target (Fabric or SQL Server). Common string, date, and decimal types keep a matching SQL Server type. These mappings differ from the MySQL type name:

MySQL type Target type
TINYINT (signed or unsigned) smallint
SMALLINT unsigned int
MEDIUMINT int
INT / INTEGER unsigned bigint
BIGINT unsigned decimal(20,0)
FLOAT real
DOUBLE / REAL float
YEAR int
TIME varchar holding the duration (for example -01:00:00.123456)
DATETIME / TIMESTAMP datetime2
TINYTEXT, TEXT, MEDIUMTEXT, LONGTEXT, JSON, ENUM, SET nvarchar(max)
GEOMETRY, POINT, LINESTRING, POLYGON, and the other spatial types varbinary(max) (WKB bytes)

String collations are mapped when the target table is created:

  • Binary MySQL collations (binary, names ending in _bin or _bin2) become Latin1_General_100_BIN2.
  • Case-sensitive collations (names containing _cs) become Latin1_General_100_CS_AS_SC_UTF8.
  • Case-insensitive collations (names containing _ci or _ai) become Latin1_General_100_CI_AI_SC_UTF8.
  • An unrecognised collation is omitted so the target database default applies.

MySQL checksums compare row counts only. A matching checksum means the counts agree. It does not compare column values.
